# Cloud Admin localization

English is the source language. `catalog.json` holds source strings, caller
context and the locale-specific glossary. Edit reviewed text in
`translations/zh-TW.json` and `translations/zh-CN.json`, then run
`npm run localization:compile`. The compiler generates both browser resources
and `internal/app/localization.generated.json`; do not edit those outputs first.

Use Taiwan developer terminology for `zh-TW` and Mainland developer terminology
for `zh-CN`. Preserve product/service names, protocol names, API fields, paths,
MQTT topics, filenames, command-line flags, JSON values, placeholders and units.
Explain an unfamiliar technical concept in plain language alongside its original
name. Keep certificate, credentials, token, device claim and JWT claims distinct.
Use caller context to distinguish physical button release from a software version,
a public Product profile key from an encryption key, and a device serial number
from a serial port.

`npm run localization:extract` records current caller filenames in the catalog.
Add the meaning, role and relevant units to ambiguous entries. Context and
glossary changes invalidate translation fingerprints, so review the affected
translations before updating their source hashes and fingerprints with
`checksums.mjs`. A translation remains `draft` until its meaning and locale
wording have been reviewed. An `approved` flag or matching hash alone does not
establish quality.

Developer Docs are a separate source under `content/developer-docs`: localized
Markdown, YAML navigation, Mermaid diagrams and HTML sequence diagrams. Review
each chapter with its linked diagrams and navigation summary. Preserve English
code fences and inline code exactly, including JSON field values. Keep source
snapshots and technical verification dates intact; they are not language-review
dates. Edit Mermaid sources and regenerate their SVGs with
`python3 tools/check_developer_docs.py --render` from the repository root.
The factory enrollment sequence is generated by
`scripts/generate-factory-enrollment-sequence.mjs`; edit that source rather than
its generated HTML/SVG.

Before approval, read the whole developer task in each locale and check:

- who acts, on which target, and with which credentials;
- prerequisites, permission boundaries, negation and success/failure conditions;
- renewal timing, retry limits, version guards and whether a service acknowledgement
  establishes that hardware completed an action;
- natural locale wording and agreement between prose, navigation, diagrams and UI.

Run `npm run localization:check`, `npm run prepare:developer-docs` and `npm test`.
`quality.mjs` checks known mistranslations, executable identifiers and technical
quantities, while the documentation builder also compares inline code and fenced
examples with English. These checks complement developer review of meaning.
