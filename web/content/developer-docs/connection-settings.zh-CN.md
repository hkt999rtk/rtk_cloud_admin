# 连接配置与服务限制

## 目标与准备工作

请根据目标环境提供的连接信息选择客户端配置，并区分哪些限制由规范定义。以下观察值于 **2026-09-04** 从当时的开发环境 Broker 读取。这些是配置记录，不是生产环境的容量保证，也不能证明每项 MQTT 功能都已完成端到端传递验证。

[打开连接检查时序图](assets/connection-check.zh-CN.html)

## 必备的环境连接信息

请将以下值记录在项目的环境配置中，不要硬编码在源码中：

| 配置值 | 来源与验证方式 |
| --- | --- |
| Account Manager HTTPS 源地址 | 账号或项目的环境配置；验证普通服务器 TLS |
| App 与设备令牌的 mTLS 源地址 | 环境公布的各角色源地址；验证客户端证书验证流程 |
| MQTT 主机名与 TLS 端口 | 已公布的 MQTT 连接配置；令牌元数据不包含这些值 |
| 服务器 CA 信任证书包 | 环境提供的信任资料；验证主机名与证书有效期 |
| MQTT 用户名与 Client ID 基础值 | 当前令牌响应的 `mqtt` 字段 |
| MQTT 密码 | 当前运行时的 `access_token` |
| HTTP Shadow 端点、区域、密钥与会话令牌 | 当前返回的 `aws_credentials` |

教程使用的 8883 端口只是可替换的示例。设备专用的 WebSocket 传输或内部 Broker 监听端点，不代表提供 MQTT over WebSocket。浏览器需要明确公布、具有身份验证的 WSS 端点以及受支持的客户端流程；本版尚未验证此路径。在端点确认前，请使用 SDK 为你的平台支持的传输方式。

## 规范定义的限制

| 项目 | 已确认的规范 |
| --- | --- |
| MQTT 教程协议 | MQTT 3.1.1；其他版本需在目标环境验证 |
| Client ID | 返回且经签名的基础值，加上允许的角色后缀；后缀限 1–64 个 ASCII 字母、数字、下划线或连字符 |
| 主题隔离 | 按已验证的 Brand Cloud 命名空间隔离；在普通主题中放入任意设备 ID，不等于逐设备访问控制 |
| MQTT Shadow 授权 | 同时需要 `mqtt` 与 `iot_shadow`，且身份主体、设备与具体主题均须获得授权 |
| HTTP Shadow 授权 | 需要 `iot_shadow`、已授权身份与已签名请求 |
| Shadow 状态大小 | 期望／上报状态合计上限 8 KiB，不含服务生成的元数据；检查的是合并后存储的状态 |
| Shadow 嵌套层数 | 最多八层 |
| Shadow `clientToken` | 最多 64 个 UTF-8 字节 |
| 命名 Shadow 列表每页条数 | 1–100 |
| 消息传递 | Shadow 通知可能重复；顺序保证以各 Shadow 为范围，详见参考文档 |

## 开发环境观察到的 Broker 配置

| Broker 配置 | 观察值 | 对开发者的影响 |
| --- | --- | --- |
| MQTT 数据包大小上限 | `1MB` | Broker 数据包上限包含协议开销；Shadow 状态仍受更小的大小限制 |
| QoS 上限 | 2 | Broker 接受的最高值；教程使用 QoS 1，不保证设备操作恰好执行一次 |
| 可使用 Retain | `true` | 仅表示 Broker 配置；仍受服务主题策略与功能验证限制，Shadow 请求不得设为保留消息 |
| 未完成确认的 MQTT 消息上限（in-flight） | 32 | 传输流量控制配置，不代表允许的 Shadow 并发请求数 |
| 会话消息队列上限 | 1000 | Broker 的有限队列，不代表离线 Shadow 通知一定会重放 |
| 会话过期时间 | `2h` | Broker 配置；不能套用为教程 Clean Session 的持久化保证 |
| Keep Alive 倍数／检查间隔 | 1.5 / `30s` | Broker 存活检查配置，不代表客户端会在精确时间点断开连接 |
| 服务器覆盖 Keep Alive | 禁用 | 教程请求 60 秒；仍须考虑网络与代理的空闲超时 |
| 主题层数上限 | 128 | Broker 上限；客户端仍须使用具体获授权的主题 |
| 通配符订阅 | Broker 层已启用 | 即使 Broker 启用此配置，Shadow ACL 仍可拒绝范围过广的通配符订阅 |

读取配置值，不能验证重连后的数据保留、保留消息重放、MQTT 5 功能、共享订阅，或你的账号能否使用 WebSocket。依赖这些行为前，请先验证对应场景。生产部署可能使用不同限制；应公布该环境的新配置，不要把这些开发环境数值直接当作通用规范。

## 请求速率、连接数与重试上限

已审查的公开规范尚未定义通用的每账号连接配额、每秒请求配额，或未完成 Shadow 请求数上限。这是仍待补充的规范与验证项。容量规划前，请先获取目标环境公布的配额；内部队列长度或 Broker 上限不等于账号配额。令牌不能提高服务使用权或配额。

集成初期，建议每个设备的每个 Shadow 同时仅保留一条尚未完成的状态变更。这是保守的客户端策略，不是服务器限制。请限制待处理请求数，对暂时性失败采用加入随机延迟的退避重试，并明确报告 429，不要无限重试。使用当前有效凭证重新连接，等待 SUBACK，再以 GET 获取 Shadow 状态。参阅[连接恢复](mqtt-connection.zh-CN.md)。

## 验收检查表

发布前，记录端点与环境配置版本，并确认：错误 CA 无法通过 TLS；已过期或属于其他设备的凭证被拒绝；具体主题订阅成功；未授权主题被拒绝；HTTP 与 MQTT 访问同一个命名 Shadow；重新连接后可通过 GET 恢复；状态超出大小限制或版本过旧时，会返回文档所述错误。未测试的功能应标记为尚未验证，不可直接视为支持。
